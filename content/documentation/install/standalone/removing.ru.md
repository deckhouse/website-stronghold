{{< alert level="danger" >}}
Удаление данных Stronghold необратимо. Без снимка хранилища и ключей распечатывания или восстановления восстановить секреты будет невозможно.
{{< /alert >}}

## Подготовка

1. Убедитесь, что Stronghold больше не используется: приложения, CI/CD и другие системы переключены на другое хранилище секретов или больше не требуют доступа.
1. Создайте финальный снимок хранилища и сохраните его вместе с ключами распечатывания или восстановления на срок, определённый вашей политикой хранения данных (см. [«Создание снимка»](../../../admin/backups/save/)):

   ```shell
   d8 stronghold operator raft snapshot save final.snap
   ```

1. Отзовите аренды динамических секретов, чтобы Stronghold удалил выданные им учётные данные во внешних системах (базах данных, LDAP, Kubernetes). Получите список механизмов секретов:

   ```shell
   d8 stronghold secrets list
   ```

   Для каждого механизма, выдающего динамические секреты, отзовите аренды по префиксу:

   ```shell
   d8 stronghold lease revoke -prefix database/
   ```

   Проверьте, что аренд не осталось:

   ```shell
   d8 stronghold list sys/leases/lookup/database/creds/
   ```

   Отключение механизма секретов командой `d8 stronghold secrets disable <PATH>` также отзывает все его аренды.

1. Если Stronghold использовался как центр сертификации [PKI](../../../user/secrets-engines/pki/), заранее выпустите сертификаты CA в другой системе и замените доверенные CA у клиентов. После удаления Stronghold списки отзыва (CRL) и OCSP перестанут обновляться.
1. Сохраните журналы аудита согласно политике хранения, если они хранятся на узлах Stronghold.

## Остановка и удаление

Выполните на каждом узле кластера:

1. Остановите и отключите сервис:

   ```shell
   systemctl stop stronghold
   systemctl disable stronghold
   ```

1. Удалите systemd-unit и перечитайте конфигурацию systemd:

   ```shell
   rm /etc/systemd/system/stronghold.service
   systemctl daemon-reload
   ```

1. Удалите данные, конфигурацию, сертификаты и бинарный файл. Пути по умолчанию соответствуют разделу [«Установка»](../installation/); если в конфигурации указаны другие каталоги (параметр `path` блока `storage`, `log_file`, файлы аудита), удалите и их:

   ```shell
   rm -rf /opt/stronghold
   ```

   Для носителей, на которых хранились данные Raft, используйте процедуру гарантированного уничтожения данных, принятую в вашей организации.

1. Удалите системного пользователя:

   ```shell
   userdel stronghold
   ```

1. Удалите правила межсетевого экрана для портов `8200` и `8201`, записи DNS и настройки балансировщика, если они создавались для Stronghold.

## После удаления

- Уничтожьте доли ключей распечатывания или восстановления и root-токены, если финальный снимок не нужно хранить, либо храните их вместе со снимком.
- Удалите ключи Stronghold в HSM или KMS, если использовалось автоматическое распечатывание, только после истечения срока хранения снимка: без них снимок нельзя будет распечатать.
- Отзовите учётные данные, которые Stronghold использовал для подключения к внешним системам (например, учётные записи механизмов секретов в базах данных).
