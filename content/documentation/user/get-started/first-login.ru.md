После настройки доступа к Deckhouse Stronghold выполните первый вход. Это позволит убедиться, что аутентификация работает корректно. Обычно для этого используют интерфейс командной строки (CLI) и команду `d8 stronghold login`. Если в вашей инсталляции доступен веб-интерфейс, войти можно и через него.

## Что должно быть готово до входа

Предполагается, что доступ к Stronghold уже настроен, как описано в разделе [«Доступ к проекту»](../access/). Для CLI-сценария должна быть установлена переменная окружения `STRONGHOLD_ADDR`.

## Что происходит при входе

Перед началом работы со Stronghold пользователь или сервис должен пройти аутентификацию.

После успешной аутентификации Stronghold:

- проверяет предоставленные данные;
- создаёт токен доступа;
- привязывает к нему политики;
- использует этот токен для последующих запросов.

Именно токен определяет, какие действия пользователь сможет выполнять в Stronghold.

## Первый вход через CLI

В типовом сценарии через OIDC выполните следующую команду:

```shell
d8 stronghold login -path=oidc_deckhouse -method=oidc -no-print
```

В зависимости от конфигурации вашей инсталляции путь аутентификации может отличаться. Если администратор сообщил другой путь, используйте его.

### Что происходит после запуска команды

После запуска команды CLI инициирует вход через настроенного OIDC-провайдера.
Как правило, происходит следующее:

- открывается браузер для завершения входа
  или CLI показывает URL, который нужно открыть вручную;
- после успешной аутентификации Stronghold выдаёт токен доступа;
- CLI использует этот токен для последующих команд.

Если браузер не открывается автоматически, скопируйте URL и откройте его вручную.

{{< alert level="info" >}}
Для CLI-аутентификации через OIDC обычно используется redirect URI на `localhost`, например `http://localhost:8250/oidc/callback`. Эти параметры определяются конфигурацией роли OIDC и настройками провайдера.
{{< /alert >}}

## Первый вход через веб-интерфейс

Если в вашей инсталляции доступен веб-интерфейс Stronghold, войти можно через него.

Используйте следующий типовой сценарий:

1. Откройте адрес веб-интерфейса Stronghold.
1. Выберите способ входа, например OIDC.
1. При необходимости укажите имя роли.
1. Нажмите кнопку входа через провайдера аутентификации.
1. Завершите аутентификацию у внешнего провайдера.

После успешного входа Stronghold откроет пользовательский интерфейс с правами, соответствующими вашей учётной записи и назначенным политикам.

## Как понять, что вход выполнен успешно

После входа через CLI убедитесь, что команды `d8 stronghold` выполняются с действующим токеном.
Например, используйте:

```shell
d8 stronghold status
```

При входе через веб-интерфейс признаком успешного входа является открытие интерфейса Stronghold без ошибки аутентификации.

## Что важно знать о токене после входа

После аутентификации Stronghold создаёт токен, который используется для последующих запросов.

Важно учитывать следующее:

- токен создаётся даже при входе через OIDC;
- токен имеет срок действия;
- набор доступных операций определяется прикреплёнными политиками;
- в CLI токен автоматически используется для следующих команд.

{{< alert level="warning" >}}
Не опирайтесь на внутреннюю структуру токена в автоматизации.
Токены Stronghold являются непрозрачными значениями,
и их формат не предназначен для анализа со стороны клиента.
{{< /alert >}}

## Если вход не работает

Если первый вход не выполняется, проверьте следующее:

- корректен ли путь аутентификации;
- доступен ли внешний OIDC-провайдер;
- не блокирует ли браузер открытие redirect URI;
- не истёк ли выданный токен.

Если используется OIDC, дополнительно убедитесь в следующем:

- redirect URI настроен корректно;
- адреса в Stronghold и у провайдера совпадают;
- используются правильные `http` / `https`, хост и порт;
- администратор настроил соответствующую роль аутентификации.

## Практические рекомендации

Используйте следующие рекомендации:

- Не сохраняйте токены в открытом виде в скриптах и заметках.
- Если вы впервые входите через OIDC, убедитесь, что браузер может открыть страницу провайдера и вернуться на локальный callback URI.
