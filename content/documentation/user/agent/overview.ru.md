Stronghold Agent — это клиентский демон для интеграции приложений со Stronghold. Он берёт на себя аутентификацию, получение и обновление токенов, а также доставку секретов в приложение без изменения его кода.

Stronghold Agent особенно полезен для приложений без встроенной поддержки систем управления секретами. Обычно это legacy-приложения, сервисы на виртуальных машинах и на bare metal, а также бинарные приложения без SDK для работы со Stronghold.

Stronghold Agent работает как посредник между приложением и сервером Stronghold:
- автоматически проходит аутентификацию;
- получает и обновляет токены;
- запрашивает секреты;
- передаёт секреты в приложение;
- помогает обновлять секреты без изменения кода приложения.

![Схема работы Stronghold Agent](/images/stronghold/agent.png)

На схеме показан типовой сценарий: Stronghold Agent получает секреты с сервера Stronghold по HTTPS, читает локальную конфигурацию и затем передаёт данные приложению через файлы конфигурации, шаблоны или переменные окружения.

## Когда использовать Stronghold Agent

Используйте Stronghold Agent в следующих случаях:
- нужно подключить к Stronghold приложение без нативной интеграции;
- приложение получает конфигурацию из файлов или переменных окружения;
- требуется автоматически обновлять секреты и токены;
- приложение работает на виртуальной машине или на bare metal;
- нужно упростить интеграцию legacy-приложения с системой управления секретами.

**Основной сценарий использования Stronghold Agent** — развёртывание на виртуальных машинах и bare-metal-серверах. В таких окружениях обычно нет нативных механизмов доставки секретов, которые доступны в Kubernetes, поэтому требуется отдельный компонент для интеграции приложения со Stronghold.

## Типовые сценарии использования

Stronghold Agent подходит для следующих сценариев:
- доставка секретов в legacy-приложения;
- работа с конфигурационными файлами, ключами и сертификатами;
- получение динамических учётные данные для баз данных;
- обновление TLS-сертификатов;
- запуск self-hosted CI/CD runner;
- интеграция приложений без SDK для работы со Stronghold.

Например, Stronghold Agent можно использовать, чтобы:
- записывать секреты в `application.properties`, `config.ini` и другие конфигурационные файлы;
- подставлять переменные окружения перед запуском приложения;
- перезагружать сервис после обновления конфигурации;
- автоматически обновлять временные учётные данные для баз данных;
- обновлять TLS-сертификаты до окончания срока их действия.

## Практические рекомендации

Чтобы начать работу быстрее и без лишних изменений в приложении, учитывайте следующее:
- заранее определите, как приложение получает конфигурацию: из файлов или через переменные окружения;
- для виртуальных машин и bare metal в первую очередь рассматривайте Stronghold Agent как основной способ интеграции;
- если приложение не поддерживает SDK, используйте механизмы доставки секретов, которые не требуют изменений в коде;
- заранее продумайте, как приложение будет реагировать на обновление секретов: перечитывать файлы, получать сигнал или перезапускаться;
- храните конфигурацию Agent и чувствительные файлы с минимально необходимыми правами доступа.
