Stronghold Agent позволяет приложениям получать секреты из Stronghold без прямой интеграции с API. Агент поддерживает рендеринг секретов в файлы, передачу секретов через переменные окружения, автоматическую аутентификацию, повторное использование токенов, обновление секретов и работу через локальный API Proxy.

На этой странице приведён обзор основных возможностей Stronghold Agent. Подробные инструкции и примеры вынесены в отдельные страницы.

## Что умеет Stronghold Agent

Stronghold Agent помогает решать следующие задачи:
- получать секреты из Stronghold без прямого обращения приложения к API;
- рендерить секреты в конфигурационные файлы;
- передавать секреты в переменные окружения дочернего процесса;
- автоматически проходить аутентификацию в Stronghold;
- сохранять и повторно использовать токен через кеш;
- обновлять токены и динамические credentials до истечения срока действия;
- проксировать запросы к API Stronghold через локальный эндпоинт.

## Основные режимы работы

Stronghold Agent поддерживает следующие режимы работы:

| Режим | Назначение | Когда использовать |
| --- | --- | --- |
| `template` | Рендеринг секретов в файл | Если приложение читает конфигурацию из файлов |
| `env_template` + `exec` | Передача секретов через переменные окружения | Если приложение читает конфигурацию из переменных окружения |
| `api_proxy` | Проксирование запросов к API Stronghold | Если приложение уже умеет работать с API Stronghold |

## Рендеринг секретов в файлы

Режим `template` позволяет создавать конфигурационные файлы, заполненные значениями из Stronghold. Этот режим подходит для приложений, которые читают настройки из файлов.

Обычно его используют в следующих случаях:
- приложение читает параметры из файлов `.conf`, `.ini`, `.yaml` или `.properties`;
- нужно передавать сертификаты, ключи или другие чувствительные данные в файлы;
- приложение не поддерживает прямую работу с API Stronghold;
- используются динамические credentials, которые нужно регулярно обновлять.

После изменения секрета Agent повторно рендерит файл. При необходимости он может запустить команду перезагрузки сервиса.

Дополнительные сведения доступны на странице [Шаблоны и рендеринг в файлы](../templating/).

## Передача секретов через переменные окружения

Режим `env_template` используется вместе с блоком `exec`. В этом случае Stronghold Agent запускает приложение как дочерний процесс и передаёт ему секреты через переменные окружения.

Этот режим подходит в следующих случаях:
- приложение читает конфигурацию из переменных окружения;
- секреты не должны записываться на диск;
- допустим перезапуск приложения при ротации секрета;
- нужно упростить работу с динамическими credentials.

При изменении секрета Agent формирует новые значения переменных окружения и перезапускает дочерний процесс.

Дополнительные сведения доступны на странице [Переменные окружения и Process Supervisor](../process-supervisor/).

## Auto-Auth

Auto-Auth автоматизирует получение токена для работы Stronghold Agent. Агент самостоятельно проходит аутентификацию, получает токен, использует его для запросов к Stronghold и при необходимости обновляет его.

Если настроен sink, Agent может записывать токен во внешний файл. Если sink не настроен, токен используется только внутри процесса Agent.

Stronghold Agent поддерживает следующие методы аутентификации:
- AppRole;
- token;
- JWT/OIDC;
- методы облачных провайдеров.

Дополнительные сведения доступны на странице [Auto-Auth](../auto-auth/).

## Кеширование и обновление

Stronghold Agent поддерживает кеширование токенов и автоматическое обновление секретов. Это позволяет снизить нагрузку на сервер Stronghold и уменьшить число повторных аутентификаций.

Agent может выполнять следующие действия:
- повторно использовать уже полученный токен;
- обновлять токен до истечения TTL;
- повторно проходить аутентификацию, если токен нельзя обновить;
- обновлять динамические credentials до завершения срока действия.

Эти механизмы помогают поддерживать непрерывную работу приложения без ручного вмешательства.

## API Proxy

Stronghold Agent может работать как локальный прокси для API Stronghold. В этом режиме приложение обращается не напрямую к серверу Stronghold, а к локальному эндпоинту Agent.

Этот режим полезен в следующих случаях:
- приложение уже умеет работать с API Stronghold;
- нужно централизованно передавать токен аутентификации;
- требуется уменьшить число прямых подключений к серверу Stronghold.

Дополнительные сведения доступны на странице [API Proxy](../api-proxy/).

## Как выбрать режим работы

Выбирайте режим работы в зависимости от того, как приложение получает секреты:
- используйте `template`, если приложению нужны файлы конфигурации;
- используйте `env_template` вместе с `exec`, если приложению нужны переменные окружения;
- используйте `api_proxy`, если приложение уже интегрировано с API Stronghold.
