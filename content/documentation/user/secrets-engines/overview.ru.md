Механизмы секретов — это компоненты, которые хранят, генерируют или шифруют данные.
Их удобно описывать с точки зрения выполняемых функций.
Механизм секретов получает набор данных, выполняет над ним определённые действия и возвращает результат.

Одни механизмы секретов только хранят и читают данные, например K/V.
Другие подключаются к внешним сервисам и генерируют динамические учётные данные по запросу.
Третьи предоставляют шифрование как услугу, генерацию TOTP-кодов, сертификаты и другие возможности.

Механизмы секретов подключаются по определённому пути в Stronghold.
Когда в Stronghold поступает запрос, маршрутизатор автоматически перенаправляет всё, что совпадает с префиксом маршрута, в соответствующий механизм секретов.
Таким образом, каждый механизм секретов определяет собственные пути и свойства.
Для пользователя механизмы секретов работают аналогично виртуальной файловой системе и поддерживают операции чтения, записи и удаления.

## Жизненный цикл механизма секретов

Большинство механизмов секретов можно включить, отключить, настроить и переместить через CLI или API.

Доступны следующие операции:

- `enable` — включает механизм секретов по указанному пути. За некоторыми исключениями механизм секретов можно включить по нескольким путям. Каждый экземпляр изолирован в рамках своего пути. По умолчанию механизм подключается по пути, совпадающему с его типом. Например, `kv` подключается по пути `kv/`.
- `disable` — отключает существующий механизм секретов. При отключении механизма все его секреты отзываются, если это поддерживается. Все данные, хранящиеся для этого механизма в физическом хранилище, удаляются.
- `move` — перемещает путь существующего механизма секретов. В процессе перемещения все секреты отзываются, поскольку сроки аренды секретов привязаны к пути их создания. Данные конфигурации механизма при этом сохраняются.
- `tune` — настраивает глобальную конфигурацию механизма секретов, например значения TTL.

{{< alert level="warning" >}}
Путь, по которому подключаются механизмы секретов, чувствителен к регистру.
Например, механизм секретов K/V, подключённый по путям `kv/` и `KV/`, рассматривается как два отдельных экземпляра.
{{< /alert >}}

После подключения механизма секретов с ним можно взаимодействовать непосредственно по его пути в соответствии с его собственным API.
Чтобы узнать, какие пути поддерживаются, используйте команду `d8 stronghold path-help`.

Точки монтирования в Stronghold не могут конфликтовать между собой.
Это накладывает два ограничения:

- нельзя создать монтирование с префиксом, совпадающим с уже существующим монтированием;
- нельзя создать точку монтирования с именем, которое является префиксом существующего монтирования.

Например, монтирования `foo/bar` и `foo/baz` могут сосуществовать, а `foo` и `foo/baz` — нет.

## Барьерное представление

Механизмы секретов получают _барьерное представление_ настроенного физического хранилища Stronghold.
Это аналог механизма chroot.

При подключении механизма секретов генерируется случайный UUID, который становится корневой директорией данных этого механизма.
При каждой записи в физическое хранилище путь дополняется директорией с этим UUID.
Поскольку слой хранилища Stronghold не поддерживает относительный доступ, например `../`, подключённый механизм секретов не может получить доступ к данным других механизмов.

Это важная функция безопасности Stronghold.
Даже вредоносный механизм не сможет получить доступ к данным другого механизма.
