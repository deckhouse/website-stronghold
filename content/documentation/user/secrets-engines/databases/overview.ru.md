Механизм секретов баз данных генерирует динамические учётные данные на основе настроенных ролей.
Он работает с разными базами данных через плагины.
Это позволяет сервисам не хранить учётные данные в открытом виде, а запрашивать их у Stronghold и использовать [механизм lease](../../../concepts/lease/).

Такой подход упрощает аудит доступа к данным.
Каждый сервис использует уникальные учётные данные, поэтому подозрительную активность можно связать с конкретным экземпляром сервиса по имени пользователя SQL.

Stronghold использует внутренний механизм отзыва учётных данных.
Это гарантирует, что пользователи базы данных становятся недействительными через некоторое время после истечения lease.

## Как это работает

Обычно процесс состоит из следующих шагов:

1. Включите механизм секретов баз данных.
1. Настройте подключение к базе данных.
1. Создайте роль с инструкциями для выдачи учётных данных.
1. Запросите учётные данные по имени роли.

Подробности настройки зависят от конкретной базы данных.
Примеры и список параметров приведены на страницах отдельных плагинов.

## Динамические и статические роли

При использовании динамических ролей Stronghold генерирует уникальную пару имени пользователя и пароля для каждого запроса учётных данных.

Некоторые плагины также поддерживают статические роли.
Статическая роль — это сопоставление роли Stronghold и пользователя базы данных в пропорции 1:1.
Для таких ролей Stronghold хранит пароль связанного пользователя базы данных и автоматически меняет его через настраиваемые интервалы времени.

Когда клиент запрашивает учётные данные для статической роли, Stronghold возвращает текущий пароль пользователя базы данных, сопоставленного с этой ролью.
Любой пользователь с соответствующими политиками Stronghold может получить доступ к этой учётной записи базы данных.

{{< alert level="warning" >}}
Не используйте для статических ролей те же root-учётные данные базы данных, которые указаны в `config/`.
Stronghold не различает обычные и root-учётные данные при смене пароля.
Если назначить root-учётные данные статической роли, после смены пароля перестанут работать все динамические и статические пользователи, управляемые этой конфигурацией базы данных.
Если нужно сменить root-учётную запись, используйте эндпоинт API `rotate-root-credentials`.
{{< /alert >}}

## Поддерживаемые базы данных

Все перечисленные базы данных поддерживают динамические роли, статические роли и смену root-учётных данных.

| База данных | Изменение root-пользователя | Динамические роли | Статические роли | Кастомизация имени пользователя | Тип учётных данных |

## Типы учётных данных

Системы баз данных поддерживают разные способы аутентификации и типы учётных данных.
Механизм секретов баз данных может управлять учётными данными, отличными от пары имени пользователя и пароля.

Параметры `credential_type` и `credential_config` для динамических и статических ролей определяют, какие учётные данные Stronghold будет генерировать и передавать плагинам баз данных.
Поддерживаемые типы учётных данных и примеры их использования приведены в документации отдельных плагинов.

## Генерация паролей

Пароли генерируются с помощью политики паролей.

Для каждой базы данных есть политика паролей по умолчанию.
Она задаёт пароль длиной 20 символов, который содержит как минимум:

- один символ в верхнем регистре;
- один символ в нижнем регистре;
- одну цифру;
- один символ дефиса.

Политика генерации паролей по умолчанию выглядит так:

```hcl
length = 20
```
