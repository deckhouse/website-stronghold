## Механизм секретов Identity

Механизм секретов `Identity` предназначен для управления идентификацией в Deckhouse Stronghold.
Он связывает аутентифицированных клиентов с сущностями и позволяет использовать эти сущности
для управления доступом.

В Deckhouse Stronghold клиенты представлены сущностями.
Каждая сущность может иметь несколько алиасов [1].

Например, один пользователь может входить через GitHub и LDAP.
В этом случае обе учётные записи можно связать с одной сущностью,
у которой будет два алиаса: GitHub и LDAP.

После успешной аутентификации через поддерживаемый бэкенд,
кроме бэкенда Token, Deckhouse Stronghold создаёт новую сущность и добавляет к ней алиас,
если подходящая сущность ещё не существует.
Идентификатор сущности затем связывается с аутентифицированным токеном.

При использовании таких токенов идентификаторы сущностей попадают в журнал аудита.
Это позволяет отслеживать действия пользователей.

Хранилище идентификаторов позволяет управлять сущностями в Deckhouse Stronghold.
Сущности и их алиасы можно создавать и связывать через ACL API.
Для сущностей также можно задавать политики, которые расширяют возможности токенов,
связанных с идентификаторами сущностей.
Эти возможности дополняют существующие возможности токена, а не заменяют их.
Возможности, унаследованные токеном от сущности, определяются динамически во время запроса.
Это позволяет гибко управлять доступом для уже выданных токенов.

{{< alert level="warning" >}}
Механизм секретов `Identity` установлен по умолчанию.
Его нельзя отключить или переместить.
Подробное описание концепции см. в разделе [Identity](../../../../concepts/identity/).
{{< /alert >}}

## Что поддерживает механизм

Механизм секретов `Identity` поддерживает следующие функции:

- [OIDC identity tokens](../oidc-token/);
- [OIDC identity provider](../oidc-provider/).
