---
title: "TOTP secrets engine"
description: "Information about TOTP secrets engine in Deckhouse Stronghold."
weight: 60
---

The TOTP secrets engine generates temporary credentials in accordance with the TOTP standard.
It also lets you create new keys and validate passwords generated with those keys.
The engine can operate in two modes: generator and provider.

## Generator mode

In generator mode, the TOTP secrets engine acts as a TOTP code generator.
In this mode, it can replace traditional TOTP generators such as Google Authenticator.
This improves security because the ability to generate codes is protected by policies, and all actions are audited.

### Configuration

Most secrets engines require initial configuration before use.
These steps are usually performed by an operator or a configuration management tool.

Enable the TOTP secrets engine:

```shell
stronghold secrets enable totp
```

Example output:

```console
Success! Enabled the totp secrets engine at: totp/
```

By default, the engine is mounted at its own name.
To enable it at a different path, use the `-path` argument.

Create a named key.
The key name is used to identify it.

```shell
stronghold write totp/keys/my-key \
  url="otpauth://totp/Stronghold:test@test.com?secret=Y64VEVMBTSXCYIWRSHRNDZW62MPGVU2G&issuer=Stronghold"
```

Example output:

```console
Success! Data written to: totp/keys/my-key
```

The `url` parameter must contain the secret key or the value from the barcode provided by a third-party service.

### Usage

After the engine is configured and a user or system receives a Stronghold token with the required permissions, credentials can be generated.

Generate a new OTP code by reading data from the `/code` endpoint and specifying the key name:

```shell
stronghold read totp/code/my-key
```

Example output:

```console
Key     Value
---     -----
code    260610
```

Using ACL, you can restrict access to the TOTP engine.
For example, trusted operators can manage key definitions, while users and applications can access only specific credentials.

## Provider mode

In provider mode, the TOTP secrets engine is used to generate new keys and validate passwords created with them.

### Configuration

Enable the TOTP secrets engine:

```shell
stronghold secrets enable totp
```

Example output:

```console
Success! Enabled the totp secrets engine at: totp/
```

By default, the engine is mounted at its own name.
To enable it at a different path, use the `-path` argument.

Create a named key with the `generate` parameter.
This tells Stronghold to operate in provider mode.

```shell
stronghold write totp/keys/my-user \
  generate=true \
  issuer=Stronghold \
  account_name=user@test.com
```

Example output:

```console
Key        Value
---        -----
barcode    iVBORw0KGgoAAAANSUhEUgAAAMgAAADIEAAAAADYoy0BA...
url        otpauth://totp/Stronghold:user@test.com?algorithm=SHA1&digits=6&issuer=Stronghold&period=30&secret=V7MBSK324I7KF6KVW34NDFH2GYHIF6JY
```

The response includes a Base64-encoded barcode and an OTP URL.
Both options are equivalent.

Provide either of them to the user who authenticates with TOTP.

### Usage

A user can validate a TOTP code generated by a third-party application:

```shell
stronghold write totp/code/my-user code=886531
```

Example output:

```console
Key      Value
---      -----
valid    true
```
