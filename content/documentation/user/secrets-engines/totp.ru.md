Механизм секретов TOTP генерирует временные учётные данные в соответствии со стандартом TOTP.
Он также позволяет создавать новые ключи и проверять пароли, сгенерированные с их помощью.
Механизм может работать в двух режимах: генератора и провайдера.

## Режим генератора

В режиме генератора механизм секретов TOTP выступает как генератор TOTP-кодов.
В этом режиме он может заменить традиционные генераторы TOTP, например Google Authenticator.
Это повышает безопасность, поскольку возможность генерации кодов защищена политиками, а все действия аудируются.

### Настройка

Большинство механизмов секретов требуют предварительной настройки перед использованием.
Обычно эти действия выполняет оператор или инструмент управления конфигурацией.

Активируйте механизм секретов TOTP:

```shell
stronghold secrets enable totp
```

Пример вывода:

```console
Success! Enabled the totp secrets engine at: totp/
```

По умолчанию механизм монтируется по имени.
Чтобы активировать его по другому пути, используйте аргумент `-path`.

Создайте именованный ключ.
Имя ключа будет использоваться для его идентификации.

```shell
stronghold write totp/keys/my-key \
  url="otpauth://totp/Stronghold:test@test.com?secret=Y64VEVMBTSXCYIWRSHRNDZW62MPGVU2G&issuer=Stronghold"
```

Пример вывода:

```console
Success! Data written to: totp/keys/my-key
```

Параметр `url` должен содержать секретный ключ или значение из штрих-кода, предоставленного сторонним сервисом.

### Использование

После настройки механизма и получения токена Stronghold с соответствующими разрешениями можно генерировать учётные данные.

Сгенерируйте новый OTP-код, прочитав данные из эндпоинта `/code` с указанием имени ключа:

```shell
stronghold read totp/code/my-key
```

Пример вывода:

```console
Key     Value
---     -----
code    260610
```

С помощью ACL можно ограничить доступ к механизму TOTP.
Например, доверенные операторы могут управлять определениями ключей, а пользователи и приложения — получать доступ только к определённым учётным данным.

## Режим провайдера

В режиме провайдера механизм секретов TOTP используется для генерации новых ключей и проверки паролей, созданных с их помощью.

### Настройка

Активируйте механизм секретов TOTP:

```shell
stronghold secrets enable totp
```

Пример вывода:

```console
Success! Enabled the totp secrets engine at: totp/
```

По умолчанию механизм монтируется по имени.
Чтобы активировать его по другому пути, используйте аргумент `-path`.

Создайте именованный ключ с параметром `generate`.
Это указывает Stronghold работать в режиме провайдера.

```shell
stronghold write totp/keys/my-user \
  generate=true \
  issuer=Stronghold \
  account_name=user@test.com
```

Пример вывода:

```console
Key        Value
---        -----
barcode    iVBORw0KGgoAAAANSUhEUgAAAMgAAADIEAAAAADYoy0BA...
url        otpauth://totp/Stronghold:user@test.com?algorithm=SHA1&digits=6&issuer=Stronghold&period=30&secret=V7MBSK324I7KF6KVW34NDFH2GYHIF6JY
```

Ответ включает штрих-код, закодированный в Base64, и OTP-ссылку.
Оба варианта эквивалентны.

Передайте один из них пользователю, который проходит аутентификацию с помощью TOTP.

### Использование

Пользователь может проверить TOTP-код, сгенерированный сторонним приложением:

```shell
stronghold write totp/code/my-user code=886531
```

Пример вывода:

```console
Key      Value
---      -----
valid    true
```
