Метод аутентификации `userpass` позволяет пользователям проходить аутентификацию в Deckhouse Stronghold с помощью имени пользователя и пароля.
Этот метод подходит для сценариев, где нужен простой локальный способ входа, не используется внешний identity-провайдер и требуется быстро выдать пользователю доступ.

## Как работает метод Userpass

Метод `userpass` хранит комбинации имени пользователя и пароля непосредственно в Stronghold.
Он не читает пользователей и пароли из внешнего источника.

Это означает следующее:

- учётные записи создаются и поддерживаются внутри Stronghold;
- права доступа определяются через политики, назначенные пользователю;
- метод не зависит от внешнего каталога, такого как `LDAP`, `OIDC` или `SAML`.

Все вводимые имена пользователей сохраняются в нижнем регистре.
Например, `Mary` и `mary` считаются одной и той же учётной записью.

## Когда использовать метод Userpass

Используйте `userpass` в следующих случаях:

- нужен простой вход по логину и паролю;
- не требуется подключать внешнюю систему аутентификации;
- администратор хочет вручную управлять списком пользователей;
- нужен базовый способ входа для локального контура, пилотного стенда или демонстрационной среды.

Если в организации уже используется корпоративная система идентификации, обычно предпочтительнее выбрать внешний метод аутентификации.

## Настройка метода

Перед тем как пользователи смогут проходить аутентификацию, включите метод и создайте пользователей.

### Включение по стандартному пути

Выполните следующую команду:

```shell
d8 stronghold auth enable userpass
```

После этого метод будет доступен по пути `auth/userpass`.

### Включение по произвольному пути

Если нужно смонтировать метод по другому пути, используйте параметр `-path`:

```shell
d8 stronghold auth enable -path=<path> userpass
```

Это может быть полезно, если в одной инсталляции требуется использовать несколько независимых точек входа с разными настройками.

## Создание пользователя

После включения метода создайте пользователя, которому будет разрешён вход.

```shell
d8 stronghold write auth/<userpass:path>/users/mitchellh \
  password=foo \
  policies=admins
```

В результате создаётся пользователь `mitchellh` с паролем `foo`, которому назначается политика `admins`.

{{< alert level="info" >}}
Путь `<userpass:path>` должен соответствовать фактическому пути монтирования метода.
Если метод включён по умолчанию, используйте путь `userpass`, а полный путь записи будет `auth/userpass/users/<имя_пользователя>`.
{{< /alert >}}

## Что получает пользователь после входа

После успешной аутентификации Stronghold выдаёт токен, к которому прикрепляются политики пользователя.
Этот токен используется для всех последующих запросов к Stronghold.
Доступные действия определяются назначенными политиками.

## Блокировка пользователя

Для метода `userpass` поддерживается механизм блокировки пользователя `user_lockout`, который защищает от подбора пароля.
Если пользователь несколько раз подряд введёт неверные учётные данные, Stronghold на некоторое время прекратит проверку учётных данных и сразу начнёт возвращать отказ в доступе.

Следующие параметры управляют блокировкой пользователя:

- `lockout_threshold` — Количество неудачных попыток входа, после которого пользователь блокируется. Значение по умолчанию — `5`.
- `lockout_duration` — Время, в течение которого пользователь остаётся заблокированным. Значение по умолчанию — `15 minutes`.
- `lockout_counter_reset` — Время, по истечении которого счётчик неудачных попыток сбрасывается, если новых попыток не было. Значение по умолчанию — `15 minutes`.

Функция блокировки пользователя включена по умолчанию.
Счётчик неудачных попыток также сбрасывается после успешного входа.

### Отключение блокировки

Функцию блокировки пользователя можно отключить через команду `auth tune`, передав значение `disable_lockout=true`.

{{< alert level="warning" >}}
Механизм `user_lockout` поддерживается только методами `userpass`, `ldap` и `approle`.
{{< /alert >}}

## Практические рекомендации

Учитывайте следующие рекомендации:

- используйте `userpass`, если нужен простой локальный вход без внешнего identity-провайдера;
- не используйте слабые пароли;
- назначайте пользователям только необходимые политики;
- учитывайте риски локального хранения учётных записей, если метод используется в production-окружении;
- при большом числе пользователей рассмотрите переход на внешний метод аутентификации.
