Метод аутентификации по токену (Token auth) является встроенным и автоматически доступен в Deckhouse Stronghold по пути `/auth/token`.

Этот метод позволяет:

- проходить аутентификацию с помощью уже существующего токена;
- использовать токены для дальнейшей работы с Deckhouse Stronghold;
- создавать новые токены;
- отзывать существующие токены при наличии соответствующих прав.

## Когда использовать Token auth

Метод `Token` обычно используют в следующих случаях:

- у пользователя или приложения уже есть действующий токен Deckhouse Stronghold;
- нужно выполнить вход без повторной аутентификации через другой бэкенд;
- используется автоматизация или интеграция с API;
- требуется работать с токеном напрямую как с основным способом доступа.

{{< alert level="info" >}}
Когда любой другой метод аутентификации успешно завершает вход, Deckhouse Stronghold всё равно создаёт токен. Поэтому Token auth можно рассматривать как базовый встроенный механизм доступа, который используется как самостоятельно, так и в результате других методов аутентификации.
{{< /alert >}}

## Как работает метод Token

Когда другой метод аутентификации возвращает идентификатор пользователя или приложения, Deckhouse Stronghold создаёт для него новый уникальный токен.

Хранилище токенов также можно использовать в обход других методов аутентификации. Вы можете создавать токены напрямую, а также выполнять с ними другие операции, например продление и отзыв.

Это означает, что в некоторых сценариях достаточно уже выданного токена, чтобы выполнять дальнейшие действия в Deckhouse Stronghold без повторного прохождения внешней аутентификации.

## Аутентификация через CLI

Для входа с использованием токена выполните следующую команду:

```shell
d8 stronghold login token=<token>
```

После этого CLI будет использовать переданный токен для последующих запросов.

Ниже приведён пример входа через метод аутентификации `userpass`:

```shell
d8 stronghold login -method=userpass \
  username=mitchellh \
  password=foo
```

## Аутентификация через API

При работе с HTTP API токен передаётся в заголовке запроса. Поддерживаются следующие варианты:

- `X-Vault-Token: <token>`;
- `Authorization: Bearer <token>`.

Ниже приведён типовой пример запроса через API:

```shell
curl \
  --request POST \
  --data '{"password": "foo"}' \
  http://127.0.0.1:8200/v1/auth/userpass/login/mitchellh
```

В ответе Deckhouse Stronghold возвращает токен в поле `auth.client_token`.

Пример ответа:

```json
{
  "lease_id": "",
  "renewable": false,
  "lease_duration": 0,
  "data": null,
  "auth": {
    "client_token": "c4f280f6-fdb2-18eb-89d3-589e2e834cdb",
    "policies": ["admins"],
    "metadata": {
      "username": "mitchellh"
    },
    "lease_duration": 0,
    "renewable": false
  }
}
```

## Что важно учитывать

При использовании Token auth учитывайте следующее:
- Token auth не требует отдельного включения, так как этот метод встроен в Deckhouse Stronghold;
- токен даёт доступ в пределах назначенных ему политик;
- если токен истёк или был отозван, аутентификация с его помощью не сработает;
- в пользовательских сценариях токен часто является результатом входа через другой метод аутентификации, например `OIDC`, `LDAP` или `userpass`.

## Практические рекомендации

Используйте следующие рекомендации:
- используйте Token auth, если у вас уже есть действующий токен Deckhouse Stronghold;
- не передавайте токены через небезопасные каналы;
- не храните токены в открытом виде в скриптах, заметках или системах без контроля доступа;
- если токен используется в автоматизации, учитывайте его TTL, возможность продления и порядок отзыва.
