Метод аутентификации `ldap` позволяет аутентифицировать пользователей с помощью существующего LDAP-сервера и корпоративных учётных данных. Это упрощает интеграцию Deckhouse Stronghold в инфраструктуру, где уже используются LDAP или Active Directory. Сопоставление LDAP-пользователей и LDAP-групп с политиками Stronghold выполняется через пути `users/` и `groups/`. При подготовке страницы сохранена обзорно-справочная структура: добавлены назначение метода, контекст использования, основные принципы работы и практические детали настройки.

## Когда использовать LDAP

Метод `ldap` подходит в следующих случаях:

- в организации уже используется LDAP-каталог или Active Directory;
- нужно аутентифицировать пользователей по корпоративным учётным данным;
- требуется сопоставить LDAP-группы с политиками Stronghold;
- необходимо интегрировать Stronghold в существующую LDAP-инфраструктуру.

## Аутентификация

### Через CLI

```bash
d8 stronghold login -method=ldap username=mitchellh
```

После запуска команды Stronghold запросит пароль. При успешной аутентификации сервис вернёт токен с назначенными политиками.

### Через API

```bash
curl \
  --request POST \
  --data '{"password":"foo"}' \
  http://127.0.0.1:8200/v1/auth/ldap/login/mitchellh
```

Пример ответа:

```json
{
  "lease_id": "",
  "renewable": false,
  "lease_duration": 0,
  "data": null,
  "auth": {
    "client_token": "c4f280f6-fdb2-18eb-89d3-589e2e834cdb",
    "policies": [
      "admins"
    ],
    "metadata": {
      "username": "mitchellh"
    },
    "lease_duration": 0,
    "renewable": false
  }
}
```

## Включение метода

Перед тем как пользователи смогут проходить аутентификацию, включите метод:

```bash
d8 stronghold auth enable ldap
```

## Конфигурация

После включения настройте подключение к LDAP-серверу, параметры поиска пользователя и способ определения членства в группах.

### Параметры подключения

Используйте следующие основные параметры:

- `url` — адрес LDAP-сервера. Можно указать один URL, например `ldap://ldap.example.com` или `ldaps://ldap.example.com:636`, либо список URL через запятую;
- `starttls` — включает использование `StartTLS` после установки незашифрованного соединения;
- `insecure_tls` — отключает проверку сертификата LDAP-сервера;
- `certificate` — CA-сертификат для проверки сертификата LDAP-сервера в формате x509 PEM;
- `client_tls_cert` — клиентский сертификат в формате x509 PEM;
- `client_tls_key` — ключ клиентского сертификата в формате x509 PEM.

### Поиск пользователя

Stronghold поддерживает два способа определения LDAP-объекта пользователя:

- поиск пользователя в директории;
- использование UPN (User Principal Name, основное имя пользователя).

#### Аутентифицированный поиск

Для аутентифицированного поиска используйте следующие параметры:

- `binddn` — имя объекта для биндинга при поиске пользователей и групп;
- `bindpass` — пароль для `binddn`;
- `userdn` — базовый DN для поиска пользователя;
- `userattr` — атрибут LDAP-пользователя, соответствующий имени пользователя;
- `userfilter` — Go-шаблон для построения фильтра поиска пользователя.

По умолчанию используется фильтр `({{.UserAttr}}={{.Username}})`. Если задан параметр `upndomain`, по умолчанию используется фильтр `(userPrincipalName={{.Username}}@UPNDomain)`.

{{< alert level="warning" >}}
Если указываете `userfilter`, включите в него шаблонизированное значение `{{.UserAttr}}` или литеральное значение, соответствующее `userattr`. Это нужно, чтобы поиск возвращал уникальный результат и не возникали коллизии при входе.
{{< /alert >}}

#### Анонимный поиск

Для анонимного поиска используйте следующие параметры:
- `discoverdn` — включает анонимное подключение для определения bind DN пользователя;
- `userdn` — базовый DN для поиска пользователя;
- `userattr` — атрибут LDAP-пользователя, соответствующий имени пользователя;
- `userfilter` — Go-шаблон для построения фильтра поиска пользователя;
- `deny_null_bind` — запрещает обход аутентификации при пустом пароле. Значение по умолчанию — `true`;
- `anonymous_group_search` — включает анонимные подключения для поиска групп. Значение по умолчанию — `false`.

{{< alert level="warning" >}}
Если указываете `userfilter`, включите в него шаблонизированное значение `{{.UserAttr}}` или литеральное значение, соответствующее `userattr`. Это нужно, чтобы поиск возвращал уникальный результат и не возникали коллизии при входе.
{{< /alert >}}

#### Использование UPN в Active Directory

Параметр `upndomain` задаёт домен для построения UPN в формате `[username]@UPNDomain`. Это особенно полезно при работе с Active Directory.

### Определение членства в группах

После аутентификации пользователя Stronghold должен определить, в какие LDAP-группы он входит. Поддерживаются два подхода:

- поиск групп, в которые входит пользователь;
- поиск объекта пользователя и чтение атрибута с перечнем групп.
Используйте следующие параметры:
- `groupfilter` — Go-шаблон для построения запроса на членство в группах;
- `groupdn` — базовый DN для поиска групп;
- `groupattr` — атрибут LDAP, используемый для определения имён групп.

По умолчанию `groupfilter` совместим с несколькими распространёнными схемами каталогов:

`(|(memberUid={{.Username}})(member={{.UserDN}})(uniqueMember={{.UserDN}}))`.

Для поддержки вложенных групп в Active Directory используйте фильтр:

`(&(objectClass=group)(member:1.2.840.113556.1.4.1941:={{.UserDN}}))`.

### Дополнительные параметры

Также поддерживаются следующие параметры:

- `dereference_aliases` — управляет тем, как алиасы разрешаются при поиске. Поддерживаются значения `never`, `finding`, `searching`, `always`;
- `username_as_alias` — если установлено значение `true`, в качестве имени алиаса используется имя пользователя, переданное при входе;
- `max_page_size` — если значение больше `0`, Stronghold использует постраничный поиск на LDAP-сервере;
- `upndomain` — задаёт домен UPN для аутентификации;
- `discoverdn` — включает автоматическое определение bind DN пользователя.

Терминология на странице приведена к каноническим формам: например, используется форма «алиас», а не альтернативные варианты.

## Примеры конфигурации

### Active Directory с StartTLS и вложенными группами

```bash
d8 stronghold write auth/ldap/config \
  url="ldap://ldap.example.com" \
  userdn="ou=Users,dc=example,dc=com" \
  groupdn="ou=Groups,dc=example,dc=com" \
  groupfilter="(&(objectClass=group)(member:1.2.840.113556.1.4.1941:={{.UserDN}}))" \
  groupattr="cn" \
  upndomain="example.com" \
  certificate=@ldap_ca_cert.pem \
  insecure_tls=false \
  starttls=true
```

### Аутентифицированный поиск с сервисной учётной записью

```bash
d8 stronghold write auth/ldap/config \
  url="ldap://ldap.example.com" \
  userattr="sAMAccountName" \
  userdn="ou=Users,dc=example,dc=com" \
  groupdn="ou=Users,dc=example,dc=com" \
  groupfilter="(&(objectClass=person)(uid={{.Username}}))" \
  groupattr="memberOf" \
  binddn="cn=stronghold,ou=users,dc=example,dc=com" \
  bindpass='My$ecrt3tP4ss' \
  certificate=@ldap_ca_cert.pem \
  insecure_tls=false \
  starttls=true
```

### Анонимный поиск с автоматическим определением bind DN

```bash
d8 stronghold write auth/ldap/config \
  url="ldaps://ldap.example.com" \
  userattr="uid" \
  userdn="ou=Users,dc=example,dc=com" \
  discoverdn=true \
  groupdn="ou=Groups,dc=example,dc=com" \
  certificate=@ldap_ca_cert.pem \
  insecure_tls=false \
  starttls=true
```

## Сопоставление LDAP-групп и политик Stronghold

После настройки подключения сопоставьте LDAP-группы с политиками Stronghold.

Пример:

```bash
d8 stronghold write auth/ldap/groups/scientists policies=foo,bar
```

Эта команда сопоставляет LDAP-группу `scientists` с политиками Stronghold `foo` и `bar`.
Можно также добавить определённого LDAP-пользователя в дополнительную группу Stronghold и назначить ему отдельные политики:

```bash
d8 stronghold write auth/ldap/groups/engineers policies=foobar
d8 stronghold write auth/ldap/users/tesla groups=engineers policies=zoobar
```

## Проверка результата

После настройки проверьте вход пользователя:

```bash
d8 stronghold login -method=ldap username=tesla
```

Если всё настроено правильно, пользователь получит токен с политиками, назначенными через его LDAP-группы и дополнительные сопоставления.

## Особенности применения политик

Сопоставление «пользователь → политики» выполняется в момент создания токена. Если членство пользователя в LDAP-группах изменится позже, это не повлияет на уже выданные токены.

Чтобы изменения вступили в силу, выполните следующие действия:

- отзовите старые токены;
- выполните повторную аутентификацию.

## Блокировка пользователя

Для `ldap` поддерживается механизм `user_lockout`. Если пользователь несколько раз подряд введёт неверные учётные данные, Stronghold на некоторое время перестанет проверять пароль и будет сразу возвращать отказ в доступе. Это помогает снизить риск подбора пароля. Функция блокировки пользователя включена по умолчанию.

Значения по умолчанию:

- `lockout_threshold` — 5 попыток;
- `lockout_duration` — 15 минут;
- `lockout_counter_reset` — 15 минут.

Функцию можно отключить через `auth tune`, передав `disable_lockout=true`.

{{< alert level="warning" >}}
Этот механизм поддерживается только методами `userpass`, `ldap` и `approle`.
{{< /alert >}}

## Экранирование DN

Важно корректно экранировать DN пользователя, DN для поиска и другие DN-значения. Метод `ldap` автоматически экранирует имя пользователя, переданное при входе, при подстановке в bind DN по правилам RFC 4514.

При использовании Active Directory учитывайте дополнительные особенности экранирования. Например, символ `#` может требовать экранирования независимо от позиции в DN. Если в имени пользователя или настроенных DN присутствуют специальные символы, проверьте корректность экранирования.

Подробнее описано в [RFC 4514](https://www.ietf.org/rfc/rfc4514.txt) и [рекомендации Microsoft по экранированию символов в Active Directory](http://social.technet.microsoft.com/wiki/contents/articles/5312.active-directory-characters-to-escape.aspx).

## Практические рекомендации

Используйте следующие рекомендации:

- Для production-окружения применяйте `ldaps` или `StartTLS`.
- Не включайте `insecure_tls` без крайней необходимости.
- Перед использованием сложных `userfilter` и `groupfilter` убедитесь, что поиск возвращает уникальный и ожидаемый результат.
- Если используется Active Directory, учитывайте особенности экранирования DN.
- После настройки обязательно проверьте, какие политики пользователь реально получает при входе.
