Методы аутентификации это модули Stronghold, которые в рамках обработки запроса в хранилище идентифицируют пользователя, выполняют аутентификацию и отвечают за назначение сущности и набора политик пользователю. В большинстве случаев Stronghold будет делегировать управление аутентификацией и принятие решений соответствующему настроенному внешнему методу аутентификации, таким, как JWT, OIDC, Kubernetes и LDAP. В качестве источников данных о пользователях с помощью указанных методов могут использоваться кластера Deckhouse Platform, Keycloak, Blitz Identity Provider, Active Directory и т.д. Наличие нескольких методов аутентификации позволяет вам использовать тот метод, который наиболее подходит для вашего использования Stronghold и вашей организации. Возможно использование нескольких методов аутентификации одновременно.

Кроме перечисленных методов, Stronghold также поддерживает `WebAuthn` для безпарольной аутентификации с помощью `FIDO2`-совместимых аутентификаторов и `passkeys`.

Stronghold также поддерживает `SAML` для браузерного `Web SSO` через внешний `SAML 2.0` Identity Provider.

## Доступные методы аутентификации

| Метод | Тип (`auth enable`) | Назначение | Редакции |
|-------|---------------------|------------|----------|
| [AppRole](../approle/) | `approle` | Аутентификация приложений и автоматизации по `role_id` и `secret_id`. | Не указано |
| [JWT](../jwt/) | `jwt` | Вход по JWT, подпись которого проверяется по ключам или JWKS. | Stronghold, Stronghold EE, Stronghold CSE |
| [OIDC](../oidc/) | `oidc` (плагин `jwt`) | Вход через OIDC-провайдера в браузере: [GitLab](../oidc/gitlab/), [Keycloak](../oidc/keycloak/), [Kubernetes](../oidc/kubernetes/). | Stronghold, Stronghold EE, Stronghold CSE |
| [Kubernetes](../kubernetes/) | `kubernetes` | Вход по токену сервисного аккаунта Kubernetes. | Stronghold, Stronghold EE, Stronghold CSE |
| [LDAP](../ldap/) | `ldap` | Вход по учётной записи LDAP или Active Directory. | Stronghold, Stronghold EE, Stronghold CSE |
| [SAML](../saml/) | `saml` | Браузерный Web SSO через внешний SAML 2.0 Identity Provider. | Stronghold EE |
| [Token](../token/) | `token` | Вход по токену Stronghold. Встроен и не может быть отключён. | Stronghold, Stronghold EE, Stronghold CSE |
| [Userpass](../userpass/) | `userpass` | Вход по имени пользователя и паролю, хранящимся в Stronghold. | Не указано |
| [WebAuthn](../webauthn/) | `webauthn` | Беспарольный вход с FIDO2-аутентификаторами и passkeys. | Stronghold, Stronghold EE |
| Kerberos | `kerberos` | Вход по Kerberos (SPNEGO). Отдельного руководства пока нет, см. [справочник API методов аутентификации](../../../reference/api/auth/). | Не указано |

Многофакторная аутентификация ([TOTP](../mfa/totp/), [Multifactor](../mfa/multifactor/)) не является отдельным методом входа: она добавляет второй фактор к перечисленным методам. Подробнее — в разделе [«2FA / MFA»](../mfa/).

Редакции указаны по странице [«Редакции»](../../../about/editions/).

## Внешние методы аутентификации

При использовании внешнего метода аутентификации, Stronghold будет вызывать внешний сервис в момент аутентификации и для последующих продлений токенов. Если статус сущности изменится во внешней системе (например, учетная запись истекает или отключена), Stronghold отклоняет запросы на продление токенов, связанных с этой сущностью. Однако существующие токены остаются действительными на первоначальный период выдачи, если они явно не отозваны в Stronghold. Рекомендуем устанавливать соответствующие TTL для токенов при использовании любых внешних методов аутентификации.

При отключении метода аутентификации, все пользователи, аутентифицированные с помощью этого метода, автоматически выйдут из системы.
