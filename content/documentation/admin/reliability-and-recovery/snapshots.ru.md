Ручной снимок позволяет сохранить текущее состояние встроенного хранилища **Deckhouse Stronghold** в файл и использовать его как резервную копию.

> Предупреждение  
> Команда `stronghold operator raft snapshot save` применима только к кластерам с интегрированным Raft-хранилищем. Если Stronghold использует `etcd`, `postgresql` или другой внешний backend, резервную копию нужно выполнять средствами самого хранилища.

## Когда использовать

Ручное создание снимка подходит для ситуаций, когда необходимо:

- создать разовую резервную копию перед важными изменениями в кластере;
- выполнить резервное копирование вне регулярного графика автоматических снимков;
- подготовить снимок для переноса состояния на другой кластер;
- сделать копию состояния для отладки или анализа.

Ручные снимки особенно полезны для pre-production окружений или в тех случаях, когда автоматические снимки еще не настроены.

## Перед началом

Перед созданием ручного снимка убедитесь, что:

- Stronghold использует встроенное Raft-хранилище как основной `storage` backend;
- Raft используется как основной backend, а не только как `ha_storage`;
- у вас есть административный доступ к кластеру или права `sudo`;
- подготовлено безопасное место для хранения файла снимка вне production-контура;
- при необходимости вы сможете связаться с держателями unseal- или recovery-ключей.

## Сохранение снимка через CLI

Для создания снимка используйте команду:

```bash
d8 stronghold operator raft snapshot save backup.snap
```

В результате Stronghold сохранит снимок в локальный файл `backup.snap`.

## Сохранение снимка через API

Для создания снимка через API используйте endpoint `GET /sys/storage/raft/snapshot`:

```bash
curl \
  --request GET \
  --header "X-Vault-Token: ${VAULT_TOKEN}" \
  "${VAULT_ADDR}/v1/sys/storage/raft/snapshot" > backup.snap
```

## Проверка снимка

После создания резервной копии рекомендуется выполнить проверку снимка, чтобы убедиться, что файл читается и содержит ожидаемую структуру данных.

Проверить снимок можно командой:

```bash
d8 stronghold operator raft snapshot inspect backup.snap
```

Или через интерфейс проверки, описанный в разделе [Проверка снимка](./inspect/).

## Практические рекомендации

При создании и хранении ручных снимков учитывайте следующие рекомендации:

- сохраняйте файл снимка в место, доступ к которому ограничен;
- после создания снимка обязательно выполняйте его проверку через `inspect`;
- не храните единственную копию снимка на том же узле, где работает кластер;
- используйте осмысленные имена файлов, включающие дату и время создания;
- для регулярного резервного копирования используйте автоматические снимки;
- если кластер участвует в схемах репликации, продумайте отдельную стратегию резервного копирования для каждого контура;
- периодически тестируйте восстановление из ручных снимков на отдельном контуре.

## Что дальше

После создания ручного снимка рекомендуется:

1. Проверить его целостность с помощью `inspect`.
2. При необходимости настроить автоматические снимки для регулярного резервного копирования.
3. Отработать процедуру восстановления из снимка на тестовом кластере.
