В standalone-установке Stronghold работает как сервис Linux (systemd) на отдельных серверах. Здесь администратор сам управляет конфигурацией, TLS-сертификатами, распечатыванием и сетью. Пошаговая установка описана в разделе [«Установка»](../../../install/standalone/installation/), параметры конфигурационного файла — в разделе [«Настройка»](../../../install/standalone/configuration/).

## Варианты развёртывания

| Вариант | Состав | Хранилище | Назначение |
| --- | --- | --- | --- |
| Одноузловой сервер | Один сервер, подготовленный командой `stronghold bootstrap service` | Raft на одном узле или `filesystem` | Тестирование, разработка, небольшие некритичные установки |
| HA-кластер | Три и более сервера: один активный узел, остальные standby | Интегрированное хранилище Raft | Production-установки с отказоустойчивостью |

Бэкенд `filesystem` не поддерживает режим HA. Для HA используйте Raft.

По умолчанию `stronghold bootstrap service` создаёт конфигурацию с хранилищем Raft.

Команда `stronghold bootstrap` также генерирует Helm-чарт и Docker-образ для развёртывания в стороннем Kubernetes. Подробнее — в разделе [«Быстрый старт»](../../../install/standalone/bootstrap/).

## Схема HA-кластера

![layout_plan_standalone.png](../../../images/layout_plan_standalone.png)

- Один узел получает блокировку в хранилище и становится активным, остальные переходят в режим standby.
- Запросы, пришедшие на standby-узел, пересылаются на активный узел или клиент перенаправляется на `api_addr` активного узла — в зависимости от настроек и состояния кластера. В Stronghold EE performance standby-узлы обслуживают чтения локально, см. [«Performance standby»](../../replication/performance-standby/).
- Raft реплицирует данные между всеми узлами: каждый узел хранит полную копию данных, зашифрованных барьером.
- Для кворума нужно как минимум три сервера. Кворум рассчитывается как `(n+1)/2` голосующих узлов. Узлы, присоединённые с `retry_join_as_non_voter = true` (флаг `-non-voter`), не участвуют в голосовании.

## Узел кластера

На каждом сервере:

- бинарный файл и конфигурация: `/opt/stronghold/stronghold`, `/opt/stronghold/config.hcl`;
- данные Raft: `/opt/stronghold/data` с правами `0700`, владелец — системный пользователь `stronghold`;
- TLS: сертификат и ключ узла и корневой CA в `/opt/stronghold/tls`. Для каждого узла выпускается свой сертификат;
- systemd-unit `/etc/systemd/system/stronghold.service`, сервис запускается от имени пользователя `stronghold` с capability `CAP_IPC_LOCK`.

Основные параметры конфигурации узла:

```hcl
cluster_addr  = "https://10.20.30.10:8201"   # адрес для Raft и пересылки запросов
api_addr      = "https://10.20.30.10:8200"   # адрес для клиентов и перенаправления
disable_mlock = true

listener "tcp" {
  address       = "0.0.0.0:8200"
  tls_cert_file = "/opt/stronghold/tls/node-1-cert.pem"
  tls_key_file  = "/opt/stronghold/tls/node-1-key.pem"
}

storage "raft" {
  path    = "/opt/stronghold/data"
  node_id = "raft-node-1"

  retry_join {
    leader_api_addr     = "https://10.20.30.11:8200"
    leader_ca_cert_file = "/opt/stronghold/tls/stronghold-ca.pem"
  }
}
```

- `api_addr` анонсируется другим узлам для перенаправления клиентов.
- `cluster_addr` анонсируется для связи между узлами. Трафик между участниками кластера всегда идёт по TLS, схема в адресе игнорируется.
- Блоки `retry_join` перечисляют узлы, к которым новый узел пытается присоединиться при старте. Присоединение выполняется через API узла-лидера (порт `8200`).
- С Raft рекомендуется `disable_mlock = true` и отключённый своп. Отдельный `ha_storage` с Raft не объявляется.

## Инициализация и распечатывание

1. Кластер инициализируется один раз, на первом узле. По умолчанию ключ распечатывания делится на 5 долей, для распечатывания нужно 3 (`-key-shares`, `-key-threshold`).
1. При Shamir seal каждый узел распечатывается отдельно после каждого перезапуска.
1. Чтобы не распечатывать узлы вручную, настройте автоматическое распечатывание:
   - [HSM через PKCS#11](../../kms-hsm/hsm/) (`seal "pkcs11"`, Stronghold EE);
   - [Yandex Cloud KMS](../../kms-hsm/yandexcloudkms/) (`seal "yandexcloudkms"`);
   - [`seal "inner-cluster"`](../../../concepts/seal/#автоматическое-распечатывание-через-inner-cluster) (Stronghold EE) — распечатанные узлы распечатывают остальные, без внешнего KMS.

Все эти механизмы seal доступны только в standalone-установке.

## Резервное копирование

- Снимки Raft создаются вручную, см. раздел [«Резервное копирование»](../../backups/overview/).
- В Stronghold EE доступны [автоматические снимки](../../backups/automated-snapshots/) по расписанию на локальный диск или в S3-совместимое хранилище. Снимки создаёт активный узел, поэтому для production храните их во внешнем объектном хранилище.

Порядок восстановления при потере кворума — на странице [«Восстановление после потери кворума»](../../../install/standalone/raft-lost-quorum-recovery/).

## Межкластерная репликация

Несколько standalone-кластеров Stronghold EE можно связать межкластерной репликацией (PR) или репликацией для аварийного восстановления (DR). Для этого secondary-кластеру нужен доступ к кластерному порту primary. Архитектура и топологии описаны на странице [«Архитектура: Stronghold и Stronghold EE»](../../replication/architecture/), сетевые требования — на странице [«Сетевые порты»](../ports/).
